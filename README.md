## 🏛️ 1. Architecture Overview

VentureOS is architected as a modern, decoupled production system designed for enterprise-grade scalability:

* **Frontend:** Next.js 14 with TypeScript, Tailwind CSS, and Framer Motion (Deployed on **Vercel**).
* **Backend:** Async FastAPI engine with sequential agent orchestration and streaming telemetry (Deployed on **Railway**).
* **Database & Vector Store:** Supabase PostgreSQL with `pgvector` HNSW indexing for high-dimensional semantic search (Hosted on **Supabase**).
* **AI Model Engine:** Google Gemini (Flash 3.5 / 3.7) for high-speed multi-agent reasoning and `text-embedding-004` / `gemini-embedding-001` for RAG chunk embeddings.

## 🤖 2. The 7 Specialised Agents

1. **CEO / Strategy Agent**: Synthesizes the core startup thesis, vision, and long-term defensive moats.
2. **Market Research Agent**: Maps ICP personas, computes TAM/SAM/SOM market sizing, and evaluates competitor landscape.
3. **Product & Tech Agent**: Formulates MVP features, technical architecture, and scalability guardrails.
4. **Marketing / GTM Agent**: Generates customer acquisition channels, viral growth loops, and brand positioning.
5. **Finance Agent**: Projects unit economics (CAC, LTV, payback period), burn rate, and runway milestones.
6. **Investment / Risk Agent**: Calculates a calibrated venture score (0–100), red flags, and funding readiness.
7. **Final Synthesis Agent**: Consolidates all outputs into a cohesive 20-section report, surfaces contrarian contradictions, and crafts actionable 30/90-day execution roadmaps.

## 🚀 3. Production Deployment Guide

VentureOS is designed to be deployed across **Vercel** (Frontend), **Railway** (Backend), and **Supabase** (Database):

```
User (Browser)
     │
     ▼
Vercel (Next.js 14 Frontend)
     │
     ▼ HTTPS API
Railway (FastAPI Python Backend)
     │
     ├── Google Gemini API (gemini-3.5-flash / 3.7)
     │
     └── Supabase PostgreSQL
            ├── startup_sessions
            ├── agent_outputs (JSONB)
            ├── analysis_events
            ├── evaluation_runs
            └── pgvector (HNSW Cosine Similarity Search)
```

---

### A. Database Deployment (Supabase)

1. Create a new project at [supabase.com](https://supabase.com).
2. Open the **SQL Editor** in your Supabase dashboard and run the migration scripts in sequential order from `database/migrations/`:
   * `001_create_startup_sessions.sql` — Base session tables and status tracking.
   * `002_create_rag_knowledge_base.sql` — `pgvector` extension, document chunks, and `match_document_chunks` RPC.
   * `003_add_multi_agent_support.sql` — Structured JSONB outputs for all 7 agents.
   * `004_add_analysis_events_and_durations.sql` — Session events and duration metrics.
   * `005_evaluation_runs_and_hardening.sql` — Automated evaluation logging and performance indexes.
3. Copy your **Supabase Project URL** and **Service Role Key** (from Settings > API).

---

### B. Backend Deployment (Railway)

1. Sign up / log in to [railway.app](https://railway.app).
2. Click **New Project** &rarr; **Deploy from GitHub repo** &rarr; Select `VentureOs`.
3. Set the **Root Directory** to `backend` (or leave as root; Railway will automatically detect the root `Procfile` and `railway.json`).
4. Under **Variables**, add the following environment variables:

| Variable | Description | Example |
| :--- | :--- | :--- |
| `ENVIRONMENT` | Deployment environment | `production` |
| `PORT` | Service port | `8000` |
| `GEMINI_API_KEY` | Google Gemini API Key | `AIzaSy...` |
| `GEMINI_MODEL` | Preferred Gemini model | `gemini-3.5-flash` |
| `SUPABASE_URL` | Your Supabase project URL | `https://xyzcompany.supabase.co` |
| `SUPABASE_KEY` | Supabase service role key | `eyJhbGciOi...` |
| `CORS_ORIGINS` | Allowed frontend URLs | `["https://your-ventureos.vercel.app", "http://localhost:3000"]` |

5. Railway will automatically build via Nixpacks and start the service with:
   ```bash
   uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
   ```
6. Copy your public Railway backend URL (e.g. `https://ventureos-backend.up.railway.app`).

---

### C. Frontend Deployment (Vercel)

1. Sign up / log in to [vercel.com](https://vercel.com).
2. Click **Add New** &rarr; **Project** &rarr; Import `Kaustubh-kodes/VentureOs`.
3. In Project Configuration:
   * **Framework Preset:** `Next.js`
   * **Root Directory:** Click edit and select `frontend`.
   * **Build Command:** `npm run build`
   * **Output Directory:** `.next`
4. Under **Environment Variables**, add:

| Variable | Value | Description |
| :--- | :--- | :--- |
| `NEXT_PUBLIC_API_URL` | `https://your-backend.up.railway.app` | The public URL of your Railway backend |

5. Click **Deploy**. Vercel will build and deploy your frontend globally on its Edge Network!

## 💻 4. Local Development Setup

### Prerequisites
* Python 3.10+
* Node.js 18+ and npm
* Supabase Account (or local Supabase CLI)

### 1. Clone Repository
```bash
git clone https://github.com/Kaustubh-kodes/VentureOs.git
cd VentureOs
```

### 2. Backend Setup
```bash
cd backend
python -m venv venv

# Windows
.\venv\Scripts\activate
# Mac/Linux
source venv/bin/activate

pip install -r requirements.txt

# Create .env from template
cp .env.example .env
# Fill in GEMINI_API_KEY, SUPABASE_URL, and SUPABASE_KEY in .env

# Start FastAPI server
uvicorn app.main:app --reload --port 8000
```
* Interactive API Documentation: `http://localhost:8000/docs`

### 3. Frontend Setup
```bash
cd ../frontend
npm install

# Create .env.local
echo "NEXT_PUBLIC_API_URL=http://localhost:8000" > .env.local

# Start Next.js development server
npm run dev
```
* Open in browser: `http://localhost:3000`

## 📊 5. Evaluation Framework & Observability

VentureOS includes a built-in automated quality evaluation suite (`backend/app/evaluation/`):

- **RAG Retrieval Quality**:
  - **Precision@K**: Evaluates top-K retrieved chunk relevance against benchmark documents.
  - **Recall@K**: Measures coverage of essential founder knowledge sources.
  - **MRR (Mean Reciprocal Rank)**: Evaluates ranking quality of retrieved context.
- **Agent Output Quality**:
  - Validates schema conformance, token utilization, hallucination mitigation, and citation accuracy.
